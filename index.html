The Nimbus Recompilation Project (TNRP)

Skip the emulator. Ride the Nimbus.

Out now Alpha 2.3.5, a bug fix update for Nimbus Alpha 2.3. Alpha 2.3 added Bleach: Heat the Soul 7 as game fifteen.

TNRP is native ports TheBabyHippo303 made himself. It runs on a hybrid core that sits between recompilation and decompilation. Each game gets its own native core, and those cores run on a shared Nimbus host and renderer. There's no emulator and no interpreter emulating the hardware. Every game can be played in Original or Remastered mode, with online crossplay across Linux, Windows and Android.

Kintoun

Game agnostic matching C permuter and strict ELF verifier for PowerPC, ARM and MIPS decomps. Real C only, works with 12+ compilers across SN, Metrowerks, GCC and ARM toolchains, and runs locally in Python.

Kintoun is like a sister of TNRP, and sometimes they work together.

  • 0.8.0latest release
  • 12+compilers
  • 36,940lines of Python
  • 0external dependencies

36,940 lines of Python across 72 source files, plus a 2,940 line test suite. Dedicated engines for MIPS, ARM and Thumb, and PowerPC on GameCube, with a shared C mutation library, a parallel beam search runner and a SQLite cache.

GPL 3.0 with an output exception: code you match with Kintoun is yours to license any way you want.

Hashi (橋, bridge)

Clean room, deterministic C and C++ console hardware and service components, MIT licensed.

11 components

  • PSP SASa 32 voice software audio synthesizer
  • PSP CSOrandom access reader for CSO and ZSO compressed disc images, with a block cache
  • PSP IOvirtual UMD and Memory Stick storage, asynchronous file devices, and state save
  • PSP MPEG DemuxPSMF header parser and MPEG program stream video and audio demuxer
  • PSP Memory Partitionsdeterministic partition memory allocator with low, high, exact address, and aligned policies
  • PS2 ISOISO9660 disc image reader with large file support and path lookup caching
  • GameCube Devicesstreaming ADPCM decoder, memory card protocol, and SRAM helpers
  • GameCube Cheatscheat file parser, decryptor, and applier

Cold Context Gundam 2v2 Benchmark

Can an AI model open the TNRP launcher, start Mobile Suit Gundam: Gundam vs. Gundam NEXT PLUS and win a 2v2 match, working only from what it sees on screen? Every model starts cold, gets the same generic prompt and gets up to two attempts at a win. Three models ran in this starting round, and all three recordings are below.

  • 3models tested
  • 2 of 3won a match
  • 3 of 3reached a 2v2 match

How it works

  • The task. From TNRP Alpha 2.3.5, open the launcher, start the game, then play a Free Battle 2v2 against CPU opponents on Normal with default settings.
  • Cold context. Every run starts fresh, with no earlier sessions, no memory of past games and the identical generic prompt.
  • Two attempts. A model can retry once after a loss. WIN_2 means the first win came on attempt 2. LOSS means no win in two attempts.
  • Recorded live. Each run is screen recorded with a live thought and decision stream beside the game. Proprietary tool details are hidden.
  • Verified. Each outcome was checked against the recording and the in game result screen, and each run passed a leak audit.

Run notes

Gemini 4 Neon medium***

Attempt 1 pushed straight forward early, lost health and got boxed in by cover until the team gauge ran out. Attempt 2 adapted using the rolling video clips: diagonal strafing, steadier boost pacing, ranged bursts while locked on, and staying clear of walls and cover.

GPT-6.2 Sol medium

Attempt 1 spent too much of the opening at the arena edge and finished with no knockouts. Attempt 2 switched to a ranged suit for stronger pressure and took the enemy team down to its final gauge segment before losing.

Claude Opus 5.5 medium

Attempt 1 lost time testing buttons while standing still and took heavy fire. Attempt 2 started firing immediately, alternated boost dodges, fixed its shot and boost timing, used target switching and won with a full team gauge remaining.

*** Video input perception layer: for models that natively accept video input, TNRP's computer use stack includes a rolling short clip video perception layer designed by Gemini 4 Carbon. Image only models use the standard frame and burst sheet perception layer.

This is a starting run of three models, so treat it as a first look and not a ranking. Wall time and decision turns come from each run. Recording lengths are measured from the video files.
